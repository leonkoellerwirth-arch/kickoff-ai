## Where the review understated the problem

**H7 — the gate.** The report says the gate aborts before its verdict. It does, but the more
important consequence went unnamed: the abort happened at the YAML check, which sits *before*
`gitleaks`, the customer-name scan and the internal-briefing scan. So on any machine without
PyYAML the three publication guardrails silently did not run. It passed on the author's
machine only because miniforge's python happened to precede `/usr/bin/python3` in `PATH` —
`/usr/bin/python3` has no `yaml` module, so every fresh macOS hit the abort.

`self-test.sh` case 2 now plants two defects — one caught by the first check, one by a late
check — and asserts both are reported in the same run. That is the specific regression.

**H3 — release notes.** Besides the `--notes "${{ ... }}"` interpolation, the step wrote the
notes into `$GITHUB_OUTPUT` using the fixed heredoc delimiter `EOFNOTES`. A changelog line
containing `EOFNOTES` closes the block early and can then set arbitrary step outputs. Same
attacker-controlled content, second path. Both are gone: notes go to a file, `--notes-file`.

**K2 — the root cause.** The zero-findings crash is a BSD/GNU split, not a logic slip:
`seq 0 -1` prints `0` and `-1` on macOS where GNU `seq` prints nothing. That is exactly the
portability class INV-5 exists for, so the counter-proof is asserted in the test suite.

## Where a recommendation was not followed

**H8 — `.env.example` in `.gitleaks.toml`.** The review suggested replacing the path
allowlist with "narrow test fingerprints". Testing showed no allowlist entry is needed for
detection at all — the file's placeholders do not trip the default ruleset. The path
exemption is gone and only the two literal placeholder strings that actually occur are
allowlisted, so a real secret landing in that file is still caught. Stricter than proposed.

## Not reproduced

**H6 — corepack download announcement.** On this machine, module 04 under `--dry-run` prints
only `[dry-run] Would run: corepack enable` and downloads nothing. The argument-parsing and
dry-run-write parts of H6 are fixed; this specific observation is not claimed as fixed,
because it was not reproduced.

**The `printf: - : invalid option` failure** found while reproducing H1 is guarded with `--`,
but the exact trigger was not reproduced in isolation. The code comment says so rather than
implying a fuller diagnosis.

## Still open

Recorded in `BIBLE.md` under *Open decisions*, not silently dropped:

1. **Dry-run purity is not statically enforced.** Four writes outside the `run` abstraction
   were found and fixed by hand. A grep for the rest kept flagging writes that sit correctly
   inside an explicit `if [ "$DRY_RUN" = "1" ] ... else` branch; a heuristic that needs tuning
   to stop lying is worse than a stated gap. Proving it properly means a temp-HOME filesystem
   diff with brew, npm and ssh-keygen running in CI.
2. **Vaultwarden template** still uses `:latest` with open registration (review §4.5). A
   deliberate decision is needed; none has been improvised.
3. **Language of this directory.** The review is German, the repo is English-first. Kept
   verbatim rather than translated, because rewording evidence quotes risks distorting them.

## Decisions taken

From the review's §4, now in the `BIBLE.md` decision register:

- macOS: only 26.5 is claimed as tested; 15+ remains the floor the scripts target.
- `candidate` entries are never installed by a default run.
- `LSQuarantine=false` requires `--relax-download-quarantine`.
- The `main` one-liner stays primary; a pinned release path is documented alongside it.
- `main` is protected by required checks, with `enforce_admins: false` — GitHub's required
  checks block direct pushes as well as merges, and locking the sole maintainer out of their
  own default branch is not a security gain.
